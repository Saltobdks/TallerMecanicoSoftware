MOTORFLOW · FASE 02

Diagrama de componentes: alta de clientes

Flujo ejecutado desde la interfaz React hasta la persistencia de un cliente y su sucursal.

InterfazAplicaciónDatosPendiente

PRESENTACIÓN

React + Vite

CustomerForm

Formulario en customer.html. Captura datos personales, dirección estructurada y sucursal.

HTTP JSON

POST /api/auth/customers

Envía el payload y el JWT en el encabezado Authorization.

SPRING BOOT

CustomerFacade

Punto único que orquesta el caso de uso de registro dentro de una transacción.

1. AuthGuardService valida JWT y rol.
2. ValidationService verifica formato, edad, foto y dirección.
3. CustomerRepository busca correo o teléfono duplicado.
4. Persiste cliente y asociación a taller.

DOMINIO Y DATOS

Reglas

AuthGuardService

Autoriza Superadmin, Administrador y Secretaria. El control vive en servidor.

Validación

ValidationService

Teléfonos de 10 dígitos, CP de 5 dígitos, fecha/edad y URL o Base64 de foto.

JPA

Repositories

Consulta de duplicados y persistencia con restricciones únicas en base de datos.

Persistencia MySQL / MariaDB

clientes

id, nombre_completo, contacto_alternativo, edad, fecha_nacimiento, teléfonos, correos, fotografía, calle, número, colonia, municipio, estado, código_postal

cliente_taller

id, customer_id, workshop_id
Relación única e idempotente para futuras sucursales múltiples.

usuarios

id, email, password (BCrypt), role, activo
Fuente de identidad y autorización.

Seguridad: los índices únicos de correo y teléfono previenen duplicados aun si dos solicitudes llegan simultáneamente. El JWT debe pasar validación de firma y rol antes de registrar.
